# v0.1.1 — Experimental reliability update

This release contains the four WAL hardening repairs made after v0.1.0 and the
2026-11-15 audit follow-up. It remains an observation engine, not a canonical
Solana state service.

- Preserve the fsynced batch prefix, drain received updates on shutdown, stop on
  terminal writer failures and reject incompatible WAL identities.
- Add opt-in whole-transaction decode/handler isolation with durable diagnostics,
  sticky degraded quality and public evidence/health snapshots.
- Add read-only tolerant-tail replay with all-source preflight and reader locks.
- Expose reconnect overlap, initial slot and retry limit; preserve initial replay
  across failed dials, resume from transaction observations and add retry jitter.
- Use one ALT/CPI normalizer and validate record identity/digest. Different
  signatures or success states at one transaction position now fail closed.
- Serialize registration/startup, own configuration copies, make WAL failure
  sticky, redact returned transport errors and reject unsafe endpoint metadata.
- Add lint, coverage and a release workflow gated on tests and security checks.

Metadata with `inner_instructions_none=true` means CPI was **not recorded**.
It is not normalized into a known-empty list. `FailClosed` remains the default;
`SkipAndFlag` is an explicit choice to discard a whole transaction's decoded
output while retaining uncertainty and raw evidence. Sink failures are fatal.

WAL v1 format and existing Event IDs remain compatible. Replay now refuses an
active writer. Source-by-source replay still cannot recover global ordering;
there is no exactly-once downstream acknowledgement or canonical completeness.
